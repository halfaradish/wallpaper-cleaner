# 工作原理

1. 读取 Wallpaper Engine 的 `workshopcache.json`，获取当前所有已订阅壁纸的 workshop ID（标题也来自这里；标注大小以 Steam 的内容记录为准，这里只作回退，见[两个数字分别是什么](管理面板.md#两个数字分别是什么)）
2. 遍历 workshop 内容目录，对比本地文件夹与订阅列表
3. 删除不在订阅列表中的文件夹，保留已订阅的壁纸

## 订阅状态是怎么判断的

「已订阅」由三路信息交叉判断：

| 来源 | 作用 |
|------|------|
| `workshopcache.json` | 订阅列表的主来源，标题取自这里（标注大小只在这里作回退，见[两个数字分别是什么](管理面板.md#两个数字分别是什么)） |
| Steam 的 `appworkshop_431960.acf` | 交叉校验。其中 `WorkshopItemDetails` 里带 `subscribedby` 的条目（部分 Steam 版本还有 `WorkshopItemsSubscribed` 小节）是**订阅记录**；`WorkshopItemsInstalled` 是**内容记录**——取消订阅后残留的目录正属于这一类，所以它**不参与**订阅判断。程序只读这个文件，**清理与浏览都不需要 Steam 正在运行**（只有面板里的取消订阅/重新订阅需要，见[取消订阅与重新订阅](管理面板.md#取消订阅与重新订阅)） |
| 目录里内容的修改时间 | 兜底：内容在 30 分钟内被改动过的目录先不删，避免碰到还在下载的壁纸（Steam 记录已写明内容装完的不受此限）。看的是目录里文件的时间而不是目录自身的 mtime——Steam 删除内容时也会刷新目录 mtime |

Steam 的这份记录只在**它比 WE 缓存新**时才被采信（谁更新就信谁）：

- **刚下载完**：Steam 在下载完成时立刻写下记录，而 Wallpaper Engine 要等它自己刷新工坊列表才更新缓存，实测可能相差几十分钟（数据见[已核实事实](已核实事实.md)）。这时 Steam 记录更新，用它兜住刚下载的壁纸，不会显示成「已取消订阅」。
- **刚取消订阅**：WE 缓存已经把它删掉，但 Steam 还没重写文件、记录里仍写着 `subscribedby`。这时缓存更新，以缓存为准，残留立刻会被列为待清理。

这些额外来源只用于**保护**：待清理名单始终由订阅列表（WE 缓存）决定，Steam 记录只能让目录被保留，不会让任何目录变成待清理。读不到（文件不存在、格式变化、Steam 正在重写）就静默降级为只看缓存。
