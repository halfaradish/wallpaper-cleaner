# 前端

管理面板的前端。仍然是**原生 HTML/CSS/JS，无构建步骤**：没有打包器、没有框架、没有 TypeScript、没有 CSS 预处理器，浏览器直接加载源码。这份文档讲的是结构约定——改动前端之前请先看这一页。

## 目录

```
static/
  index.html                 结构。不含任何逻辑与样式
  css/
    tokens.css               设计令牌：色阶、间距、字号、圆角、层级、动效（唯一允许字面色值的文件）
    base.css                 重置、排版基线、焦点、滚动条、噪点、动效偏好、强制颜色模式
    layout.css               外壳布局：导航栏、顶栏、工具条、内容区、状态栏、窄屏
    components.css           可复用零件：按钮、表单、表格、徽章、弹窗、进度、日志、Toast
    views.css                各视图的排布与响应式
  js/
    main.js                  入口：接线、启动顺序、顶层错误上报
    core/
      config.js              面板 token 与版本号（来自 <meta>）
      prefs.js               界面偏好（主题、导航栏状态）的读写
      dom.js                 查询、显隐，以及元素工厂 h()
      format.js              体积、路径、标题等纯格式化函数
      api.js                 与后端的唯一出口：token、超时、错误归一、连接状态
      store.js               单一状态 + 渲染订阅 + 忙碌标记 + 视图切换广播
      poll.js                具名定时器表，按需跟着窗口可见性暂停/恢复
      job.js                 长任务的统一轮询
      sort.js                三态循环排序
    ui/
      motion.js              动效系统：计数滚动、整页交叉淡入、行离场
      overlay.js             原生 <dialog> 的关闭守卫与退场动画
      toast.js               可堆叠的提示条
      statusbar.js           状态栏（唯一写它的地方）
      progress.js            任务进度的两个落点（状态栏 / 弹窗）
      skeleton.js            表格骨架屏
      empty.js               组合式空状态
      result.js              上一次操作的结果面板
      connection.js          后端失联横幅、自动重连、令牌失效提示
      theme.js               主题三态循环（跟随系统 / 浅色 / 深色）
      lightbox.js            放大看预览图
    views/
      nav.js                 导航栏：视图切换、展开收起、计数徽章
      shell.js               顶栏路径行、提示条、状态栏常态文字
      stats.js               工具条上的四个数字
      steam.js               Steam 徽标、探测、连接引导
      table.js               两张表共用的行零件与勾选（含 Shift 连选）
      orphans.js             「待清理」视图
      subscribed.js          「已订阅」视图
      settings.js            「设置」视图：位置设置、运行日志、关于、检查更新
      dialogs.js             弹窗登记表（谁能关、谁不能关）
      busy.js                忙碌标记落到界面上的样子
      scan.js                扫描
      actions.js             清理 / 取消订阅 / 重新订阅
```

依赖方向大体是单向的：`core` → `ui` → `views` → `main`。`views` 之间必要的互相调用（比如 `actions.js` 调 `scan.js`）是允许的，但不能成环。

## 四条硬规矩

### 1. 组件样式里不许出现字面颜色

所有颜色都必须走 `tokens.css` 里的语义令牌。这不是洁癖：浅色主题就是靠 `@media (prefers-color-scheme: light)` 把语义层重新指一遍实现的，只要组件里还写着一个 `#rrggbb` 或 `rgb()`，换主题时它就不会跟着变，而这种漏网只在浅色下才显形。

`tests/test_static.py` 会拦住漏网的色值。字号同理——一律用 `rem`，浏览器缩放与系统文字大小才会跟着变；只有 1px 边框、圆角、图标这类"不该随字号缩放"的尺寸用 px。

**tokens.css 里不能在 `@media` 内写裸 `:root` 选择器。** 测试的 CSS 扫描器会把任何 `@media` 里的 `:root` 当成基础主题块覆盖掉，浅色主题会静默失效。动效偏好那类令牌覆盖写在 `base.css`。

### 2. 用户数据一律走 textContent

视图不再拼 HTML 字符串，而是用 `core/dom.js` 的 `h(tag, props, children)` 建节点。理由是安全：字符串拼接时，标题、路径、错误信息全都要记得 `esc()`，而"有没有忘"只能靠人眼逐个检查；改成元素工厂之后，用户数据走 `textContent`，注入这条路从"要记得防"变成"根本不存在"。

`esc()` 还留着，但只服务于极少数场景（内联 SVG 图标常量）。

### 3. 新增模块不用改白名单

`web.py` 的静态资源白名单是**扫目录得来的**，不是手写清单（漏一个就是一个只在浏览器控制台里看得见的 404）。它以目录树的 mtime 为缓存键，所以新加文件不用重启面板，刷新页面即可。

也正因如此，`tests/test_static.py` 会检查：`index.html` 引用的每个资源、每个模块 `import` 的目标都存在且在白名单里，而且 `import` 的名字确实被目标模块导出过——没有打包器时，"导出名写错"只会在浏览器里报一句 `does not provide an export named`，然后整块功能白屏。

### 4. 页面里不许有内联脚本或样式

面板带 `Content-Security-Policy`，`script-src` 只有 `'self'`，没有 `unsafe-inline`。所以：

- 面板 token 与版本号通过 `<meta name="panel-token">` / `<meta name="panel-version">` 传递（原先写在内联 `<script>` 里，那会逼着 CSP 放行 `unsafe-inline`，等于留着"注入脚本也能读到 token"这条路）；
- **`style="..."` 属性也是被拦的**，包括 JS 拼出来的那种。需要动态样式就走 CSSOM（`el.style.setProperty(...)`），CSP 不管 CSSOM 操作。行入场动画的错峰因此靠 `nth-child` 的 `animation-delay` 表，而不是逐行写 `style="--i:3"`。

## 加东西的时候

**加一个视图**：在 `views/` 下写模块，导出 `initXxx()`（里面用 `onRender(renderXxx)` 登记渲染函数），在 `main.js` 的 `bootstrap()` 里调一次，在 `index.html` 里加一个 `<section class="view" data-view="xxx">`，再在导航栏加一个 `.rail-item[data-view="xxx"]`。`views/nav.js` 的 `switchView()` 会处理剩下的（标题、按钮显隐、入场方向）。

**加一个弹窗**：HTML 里写成 `<dialog class="dialog" id="dlg-xxx"><div class="dialog-inner">…`，然后在 `views/dialogs.js` 里 `registerDialog('dlg-xxx', { dismissible, canClose })`。焦点陷阱、Esc、背景 inert、top-layer 全部由原生 `<dialog>` 负责，不需要自己写。`canClose()` 返回 false 就拒绝关闭（任务进行中不许关进度弹窗就是靠它）。

**加一条提示**：`toast(message, kind)`，`kind` 取 `'ok' | 'error' | ''`。会同时存在多条，各自计时，悬停暂停。

**改界面偏好**：`GET /api/prefs` 读、`POST /api/prefs`（带令牌）写，目前有 `theme` 与 `rail`。写的是**部分更新**：只提交要改的键，未知键原样保留。写失败会返回 500 与可读的原因——界面已经先变了，只是存不下来，这时要如实说而不是假装成功。

**加一个"操作结果"**：用 `showResult({ kind, title, summary, note, actions })`。结果面板是常驻的，适合放"跳过/失败的分类明细"这类需要读完的信息——一行提示放不下，更留不住。

**加一个空状态**：用 `renderEmpty(container, { icon, title, desc, action, actionLabel })`。`action` 是 `data-action` 的值，由 `main.js` 统一委托处理。

## 动效：每条都要说得出理由

动效集中在 `ui/motion.js` 与令牌里的 `--dur-*` / `--ease-*`。加动效前先问一句"它传达了什么"，答案只能是这四种之一：**层级**（把注意力引到对的地方）、**叙事**（按顺序揭示）、**反馈**（确认用户做了什么）、**状态转换**（说明东西变了）。答不上来就不加。

现有的几条：视图切换（状态转换）、首屏错峰入场（层级）、统计数字滚动（反馈）、进度条补间（反馈）、行选中强调条（反馈）、行移除淡出（叙事）、弹窗缩放淡入（状态转换 + 层级）、主题交叉淡入（状态转换）、按钮 hover 抬 1px / active 缩 0.985（触感）。

两条纪律：

- **只动 `transform` 与 `opacity`**，不动 `width` / `height` / `top` / `left`。
- **`prefers-reduced-motion: reduce` 时全部退化为瞬时**。CSS 侧由 `base.css` 里一条 `*` 覆盖把时长压到 1ms、延迟清零（延迟也必须清，否则错峰入场仍然"在动"，只是动得看不见）；JS 侧 `countUp` 直接落终值、`viewTransition` 不启用。

## 主题：为什么浅色令牌写了两遍

浅色那几十行声明在 `tokens.css` 里出现了两次，用哨兵注释圈着：

- `:root[data-theme="light"]` —— 用户手动选了浅色（系统是深色时也生效）
- `@media (prefers-color-scheme: light) { :root:not([data-theme="dark"]):not([data-theme="light"]) { … } }` —— 跟随系统且系统是浅色

躲不掉：**媒体查询没法写进选择器列表**，而这两种情况必须都能命中。也没用 `light-dark()`——它要 Chromium 123+，面板跑在 WebView2 里，版本偏旧时整套颜色会一起失效，失败得太难看。

既然躲不掉，就用 `tests/test_static.py` 里那条哨兵比对盯着：两段必须逐字相同，改一处忘了另一处会直接变成一次测试失败，而不是用户那边的半套配色。

`data-theme` 的三个值里只有两个有自己的 CSS 块——`auto` 靠"两个 data-theme 分支都不命中"落到媒体查询上，所以**不要**给 `auto` 也写一个块，那会让它不再跟随系统。

主题偏好存在服务端的 `prefs.json`（见 [配置与日志](配置与日志.md)），并由服务端注入 `<html data-theme>`。原因见 [管理面板](管理面板.md) 的「外观」：桌面模式的端口每次都变，localStorage 靠不住；注入第一帧同时也消掉了主题闪烁。

## 几个不那么显然的取舍

**字体只用系统栈。** 这是个离线工具，唯一联网处是「检查更新」；界面又以中文为主，而 CJK 网络字体动辄 5–15MB。所以正文优先 Win11 的 `Segoe UI Variable Text`（Win10 落到 `Segoe UI`），标题与大号数字用同族的 Display 变体，中文由雅黑接住。等宽栈里故意把 CJK 等宽（`Sarasa Mono SC` 之类）排在 `Consolas` 前面：日志正文是中文，Consolas 没有 CJK 字形、会回退成非等宽，中英混排就对不齐了。

**数字全部等宽。** 比例数字在数值变化时宽度会跳（1 比 8 窄），统计数字滚动、进度百分比刷新、文件大小排序时整列都会跟着抖。`base.css` 里把统计值、大小列、ID、计数徽章统一设了 `font-variant-numeric: tabular-nums`，一次去掉整类抖动。

**中文标签不用 `uppercase` 做小标题。** 那是照拉丁大写小标题调的，而界面上这些标签全是中文，`uppercase` 对汉字完全无效，真正落地的只有过松的字距。现在统一走 `.label` 与令牌里的 `--track-label: 0.02em`。

**页面不整体滚动。** `body` 固定成窗口大小，只有表格区与设置视图内部滚。顶栏、工具条、状态栏在 560px 高的最小窗口里也必须是稳定的参照物；整页滚动时它们会跟着走，表头也保不住。

**窄屏断点对齐窗口最小宽度。** 桌面窗口 `min_size` 是 780×560。1024 收「类型」列，900 收「标注大小」列并强制收起导航栏。之所以在 900 以下连折叠按钮一起隐藏：留一个按不动的按钮比没有按钮更让人困惑。

**进度分两个落点。** 扫描走状态栏上沿那条 2px 细线（打开面板会自动扫一遍，每次都拿全屏模态挡住整页代价太大）；清理 / 取消订阅 / 重新订阅用模态（文件正在被删，这时本来也不该乱点）。任务轮询是唯一在窗口不可见时**不暂停**的轮询：最小化期间任务照样在跑，停下来只会让界面在恢复时显示一个早已过期的状态。

**勾选状态不只靠颜色。** 选中行除了淡蓝底还有左侧一条 3px 强调条；「已取消订阅」与「无法确定的文件夹」共用琥珀色相，靠实心/虚线描边区分，而不是多引入一个色号。

**图标是手写内联 SVG。** 这是对设计规范里"用图标库"那条的刻意偏离：CSP 是 `default-src 'none'`，项目零第三方依赖、不允许 CDN，图标库引不进来。补偿办法是统一到一个家族、统一 `stroke-width`、统一 24 格网格。

## 验收

```bash
python -m unittest discover -s tests -v      # 含 tests/test_static.py 的前端守卫
python packaging/build.py                    # 打包 + 冒烟（会顺着 import 走一遍整张模块图）
```

浏览器侧建议过一遍：纯键盘走完「扫描 → 勾选 → 清理 → 看结果」；Windows 高对比度主题下看一遍（勾选框是自绘的，`base.css` 里有专门的 `forced-colors` 块）；系统设置里关掉动画看一遍；窗口缩到最小看一遍；两套主题各看一遍。

`tools/ui_sandbox.py` 会造一个假的 Wallpaper Engine 目录树（含各种边界情形：无标题、内容已缺失、来源不明的文件夹、已订阅但未下载），用 `WALLPAPER_CLEANER_HOME` 把配置与日志关进沙箱，**不会碰真实的 WE 目录**：

```bash
python tools/ui_sandbox.py "$TEMP/wc-ui-sandbox"
WALLPAPER_CLEANER_HOME="$TEMP/wc-ui-sandbox" python wallpaper-cleaner.py --web --port 8799
```

`tools/ui_sandbox_noconfig.py` 额外把自动探测也替换成"什么都没找到"，用来验证未配置时的界面。

> 在自动化浏览器里跑这套验证时有个坑：后台标签页收不到 `requestAnimationFrame` 回调，
> 而 Playwright 的可操作性检查要等两帧稳定，于是 `click()` 会一直超时。
> 用 `evaluate` 里派发真实事件代替点击，并把 `countUp` 之类的 rAF 动效当作"已落终值"来断言即可。
