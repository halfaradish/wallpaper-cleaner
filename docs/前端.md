# 前端

管理面板的前端。仍然是**原生 HTML/CSS/JS，无构建步骤**：没有打包器、没有框架、没有 TypeScript、没有 CSS 预处理器，浏览器直接加载源码。这份文档讲的是重构后的结构约定——改动前端之前请先看这一页。

## 目录

```
static/
  index.html                 结构。不含任何逻辑与样式
  css/
    tokens.css               设计令牌：色阶、间距、字号、圆角、阴影、层级、动效
    base.css                 重置、排版基线、焦点、滚动条、动效偏好、强制颜色模式
    components.css           可复用零件：按钮、表单控件、表格、徽章、弹层、进度、结果面板
    views.css                页面级排布：顶栏、内容容器、概览、卡片外壳、抽屉骨架、响应式
  js/
    main.js                  入口：注册各视图的渲染函数、绑定事件、启动
    core/
      config.js              面板 token 与版本号（来自 <meta>）
      dom.js                 取元素与显示/隐藏
      format.js              体积、路径、时间等纯格式化函数
      api.js                 与后端的唯一出口：token、超时、错误归一、连接状态
      store.js               单一状态 + 渲染订阅 + 忙碌标记
      poll.js                具名定时器表，跟着窗口可见性暂停/恢复
      job.js                 长任务的统一轮询
      sort.js                三态循环排序
    ui/
      overlay.js             弹层与抽屉的统一控制器（开关、Esc 栈、焦点、inert）
      toast.js               可堆叠的提示条
      notice.js              提示条元素的小工具
      progress.js            任务进度的两个呈现面（模态弹窗 / 顶栏内联条）
      skeleton.js            表格骨架屏
      empty.js               组合式空状态
      result.js              上一次操作的结果面板
      connection.js          后端失联横幅、自动重连、令牌失效提示
      theme.js               主题三态循环（跟随系统 / 浅色 / 深色）
      lightbox.js            放大看预览图
    views/
      topbar.js              顶栏副标题、提示条
      stats.js               概览四个数字与占比条
      steam.js               Steam 徽标、探测、连接引导
      rows.js                两张表共用的行零件与行勾选
      orphans.js             「待清理」列表
      subscribed.js          「已订阅壁纸」列表
      busy.js                忙碌标记落到界面上的样子
      scan.js                扫描
      actions.js             清理 / 取消订阅 / 重新订阅
      drawer.js              高级抽屉：位置设置、运行日志、关于、检查更新
```

依赖方向是单向的：`core` → `ui` → `views` → `main`。`views` 之间尽量不互相引用（要触发别的视图的行为就发 `data-action`，由 `main.js` 统一委托），这样不会出现循环依赖。

## 三条硬规矩

### 1. 组件样式里不许出现字面颜色

所有颜色都必须走 `tokens.css` 里的语义令牌。这不是洁癖：浅色主题就是靠 `@media (prefers-color-scheme: light)` 把语义层重新指一遍实现的，只要组件里还写着一个 `#rrggbb` 或 `rgb()`，换主题时它就不会跟着变，而这种漏网只在浅色下才显形。

`tests/test_static.py` 会拦住漏网的色值。字号同理——一律用 `rem`，浏览器缩放与系统文字大小才会跟着变；只有 1px 边框、圆角、图标这类"不该随字号缩放"的尺寸用 px。

### 2. 新增模块不用改白名单

`web.py` 的静态资源白名单是**扫目录得来的**，不是手写清单（漏一个就是一个只在浏览器控制台里看得见的 404）。它以目录树的 mtime 为缓存键，所以新加文件不用重启面板，刷新页面即可。

也正因如此，`tests/test_static.py` 会检查：`index.html` 引用的每个资源、每个模块 `import` 的目标都存在且在白名单里，而且 `import` 的名字确实被目标模块导出过——没有打包器时，"导出名写错"只会在浏览器里报一句 `does not provide an export named`，然后整块功能白屏。

### 3. 页面里不许有内联脚本或样式

面板带 `Content-Security-Policy`，`script-src` 只有 `'self'`，没有 `unsafe-inline`。所以：

- 面板 token 与版本号通过 `<meta name="panel-token">` / `<meta name="panel-version">` 传递（原先写在内联 `<script>` 里，那会逼着 CSP 放行 `unsafe-inline`，等于留着"注入脚本也能读到 token"这条路）；
- 需要动态样式就改元素的 `style` 属性或走 CSSOM（CSP 管的是内联 `<style>` 元素与 `style=` 属性，不管 CSSOM 操作）。

## 加东西的时候

**加一个视图**：在 `views/` 下写模块，导出 `initXxx()`（里面用 `onRender(renderXxx)` 登记渲染函数），然后在 `main.js` 的 `bootstrap()` 里调一次。事件绑定统一写在 `main.js` 的 `bind()` 里——"哪个控件连到哪个处理函数"只需要看一个文件。

**加一个弹窗**：HTML 里写成 `<div class="overlay hidden" id="xxx-overlay"><div class="dialog">…`，然后在视图的 `initXxx()` 里 `registerOverlay('xxx-overlay', { close })`。控制器会自动补上 `role="dialog"`、`aria-modal`、`aria-labelledby`，并处理打开时送焦点、关闭时归还焦点、锁背景（`inert`）、Tab 循环、Esc 只关最上层。非模态的面板（像高级抽屉）传 `modal: false`；不想被点遮罩关掉就再传 `dismissible: false`。

**加一条提示**：`toast(message, kind)`，`kind` 取 `'ok' | 'error' | ''`。会同时存在多条，各自计时，悬停暂停。

**改界面偏好**：`GET /api/prefs` 读、`POST /api/prefs`（带令牌）写，目前只有 `theme`。写失败会返回 500 与可读的原因——界面已经先把主题换过去了，只是存不下来，这时要如实说而不是假装成功。

**加一个"操作结果"**：用 `showResult({ kind, title, details, note, actions })`。结果面板是常驻的，适合放"跳过/失败的分类明细"这类需要读完的信息——一行提示放不下，更留不住。

**加一个空状态**：用 `emptyMarkup({ icon, title, desc, action, actionLabel })`。`action` 是 `data-action` 的值，由 `main.js` 统一委托处理。

## 主题：为什么浅色令牌写了两遍

浅色那 60 行声明在 `tokens.css` 里出现了两次，用哨兵注释圈着：

- `:root[data-theme="light"]` —— 用户手动选了浅色（系统是深色时也生效）
- `@media (prefers-color-scheme: light) { :root:not([data-theme="dark"]):not([data-theme="light"]) { … } }` —— 跟随系统且系统是浅色

躲不掉：**媒体查询没法写进选择器列表**，而这两种情况必须都能命中。也没用 `light-dark()`——它要 Chromium 123+，面板跑在 WebView2 里，版本偏旧时整套颜色会一起失效，失败得太难看。

既然躲不掉，就用 `tests/test_static.py` 里那条哨兵比对盯着：两段必须逐字相同，改一处忘了另一处会直接变成一次测试失败，而不是用户那边的半套配色。

`data-theme` 的三个值里只有两个有自己的 CSS 块——`auto` 靠"两个 data-theme 分支都不命中"落到媒体查询上，所以**不要**给 `auto` 也写一个块，那会让它不再跟随系统。

主题偏好存在服务端的 `prefs.json`（见 [配置与日志](配置与日志.md)），并由服务端注入 `<html data-theme>`。原因见 [管理面板](管理面板.md) 的「外观」：桌面模式的端口每次都变，localStorage 靠不住；注入第一帧同时也消掉了主题闪烁。

## 几个不那么显然的取舍

**字体只用系统栈。** 这是个离线工具，唯一联网处是「检查更新」；界面又以中文为主，而 CJK 网络字体动辄 5–15MB。所以正文优先 Win11 的 `Segoe UI Variable Text`（Win10 落到 `Segoe UI`），中文由雅黑接住。等宽栈里故意把 CJK 等宽（`Sarasa Mono SC` 之类）排在 `Consolas` 前面：日志正文是中文，Consolas 没有 CJK 字形、会回退成非等宽，中英混排就对不齐了；装了就优先用，没装照样落到 Consolas。

**中文标签不用 `uppercase` 做小标题。** 原先 `th` 与段标题上有 `text-transform: uppercase` 加 `letter-spacing: 0.04–0.06em`——那是照拉丁大写小标题调的，而界面上这些标签全是中文，`uppercase` 对汉字完全无效，真正落地的只有过松的字距。现在统一走 `.label` 与令牌里的 `--track-label: 0.02em`。

**窄屏断点对齐窗口最小宽度。** 桌面窗口 `min_size` 是 780×560，内容区约 764px，而原先的折叠断点是 760px——在桌面窗口里永远不触发（等于死代码），而最小宽度下七列表格会横向溢出。现在分两级：1024 收「类型」列，900 再收「标注大小」列。

**进度分两个面。** 扫描走顶栏内联条（打开面板会自动扫一遍，每次都拿全屏模态挡住整页代价太大）；清理 / 取消订阅 / 重新订阅仍用模态（文件正在被删，这时本来也不该乱点）。

**勾选状态不只靠颜色。** 选中行除了淡蓝底还有左侧一条 2px 强调条；「已取消订阅」与「无法确定的文件夹」共用琥珀色相，靠实心/虚线描边区分，而不是多引入一个色号。

## 验收

```bash
python -m unittest discover -s tests -v      # 含 tests/test_static.py 的前端守卫
python packaging/build.py                    # 打包 + 冒烟（会顺着 import 走一遍整张模块图）
```

浏览器侧建议过一遍：纯键盘走完「扫描 → 勾选 → 清理 → 看结果」；Windows 高对比度主题下看一遍（勾选框是自绘的，`base.css` 里有专门的 `forced-colors` 块）；系统设置里关掉动画看一遍；窗口缩到最小看一遍；两套主题各看一遍。

`tools/ui_sandbox.py` 会造一个假的 Wallpaper Engine 目录树（含各种边界情形：无标题、内容已缺失、来源不明的文件夹、已订阅但未下载），用 `WALLPAPER_CLEANER_HOME` 把配置与日志关进沙箱，**不会碰真实的 WE 目录**：

```bash
python tools/ui_sandbox.py "$TEMP/wc-ui-sandbox"
WALLPAPER_CLEANER_HOME="$TEMP/wc-ui-sandbox" python wallpaper-cleaner.py --web --port 8799
```

`tools/ui_sandbox_noconfig.py` 额外把自动探测也替换成"什么都没找到"，用来验证未配置时的界面。
