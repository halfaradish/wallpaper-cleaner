# 配置与日志

## 配置文件 (`config.yml`)

配置采用 YAML 格式，支持用 `#` 编写注释：

```yaml
# Wallpaper Engine 的 workshop 订阅缓存文件路径
json_path: D:\Steam\steamapps\common\wallpaper_engine\bin\workshopcache.json

# workshop 壁纸内容存放目录
workshop_dir: D:\Steam\steamapps\workshop\content\431960

# 取消订阅/重新订阅用的 steam_api64.dll（可填文件或所在目录），留空则自动查找
steam_dll_path: ""
```

| 字段 | 说明 |
|------|------|
| `json_path` | Wallpaper Engine 的 workshop 缓存文件路径 |
| `workshop_dir` | workshop 壁纸内容存放目录 |
| `steam_dll_path` | 可选。取消订阅/重新订阅用的 `steam_api64.dll`，可填文件或所在的目录；留空则自动查找（优先用 Wallpaper Engine 自带的那份） |

路径支持绝对路径和相对路径（相对路径基于配置所在目录）。Windows 路径可不加引号直接书写（引号内的内容不会被转义处理）。

> 兼容说明：旧版 `config.json` 仍会被自动读取；重命名为 `config.yml` 后即可使用注释功能。

## 配置文件与日志放在哪

| 运行方式 | 位置 |
|---|---|
| 源码运行 | 项目根目录下的 `config.yml` 与 `logs/` |
| 运行 exe | **exe 所在的那个文件夹**（解压出来的目录） |
| exe 目录不可写时 | 自动退回 `%APPDATA%\wallpaper-cleaner\`，即 `C:\Users\<你的用户名>\AppData\Roaming\wallpaper-cleaner` |
| 设了环境变量 | `WALLPAPER_CLEANER_HOME` 指定的目录（优先级最高） |

打包版默认把配置与日志写在 exe 旁边，也就是解压出来的那个文件夹里。这样它就是便携的：整个文件夹拷到 U 盘或另一台机器上，设置和日志跟着走；不想要了，删掉这一个文件夹就等于卸载干净。

**为什么不要直接在压缩包里双击 exe。** 那样运行时 Windows 会先把 exe 解到临时目录，配置就会落在那个随时会被系统清掉的地方。请先解压到一个自己的文件夹再运行。

**放进 `Program Files` 会怎样。** 那里的写权限通常只给管理员，程序启动时会先试写一个临时文件来确认能不能写：不能写就自动退回 `%APPDATA%\wallpaper-cleaner\`，并把这件事写进日志、同时显示在面板「设置 → 关于」里，不会静默地换个地方存。想让它跟着 exe 走，把 exe 换到可写的文件夹即可。

同目录下还有一个 `prefs.json`，存的是界面偏好（主题 `auto` / `light` / `dark`，以及导航栏的展开状态）。它和 `config.yml` 刻意分开：那份配置要保留你手写的注释，而界面偏好会被面板随时改写。这个文件不存在也没关系（当作跟随系统），内容损坏了也会被忽略并重新写入——一个显示偏好不该让面板打不开。

## 日志

每次运行会在 `logs/` 目录下生成日志文件，记录删除和保留的详细信息。日志按天分文件，单文件最大 5MB，保留 5 个备份。

日志默认只记 INFO 及以上——HTTP 请求、Steam 状态这类 DEBUG 过程行平时是噪音，只有排障才需要。要拿全量日志复现问题时，加 `--verbose` 运行：

```bash
python wallpaper-cleaner.py --verbose
```

超过 14 天的旧日志会在启动时自动清理，不用手动维护这个目录。

面板导航栏「设置」里的「运行日志」可以直接查看这些文件，左上角的下拉可以按级别过滤（默认隐藏 DEBUG）。
