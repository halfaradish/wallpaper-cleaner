# 已核实事实

这份文档汇总对 Wallpaper Engine / Steam 实际行为的结论，以及每条结论的依据。各篇正文只写「怎么用」，依据与实测数据集中放在这里，避免同一段解释在多处维护。

发现结论过期时改这里，并检查「出处」指向的正文是否也要跟着改。

| 结论 | 依据与实测数据 | 出处 |
|------|----------------|------|
| Steam 的订阅记录与 WE 缓存**谁新信谁**，两者相差几十分钟是常态 | 刚下载完：Steam 在下载完成时立刻写记录，Wallpaper Engine 要等自己刷新工坊列表才更新缓存，实测可差几十分钟；刚取消订阅：WE 缓存先删掉，Steam 还没重写文件、记录里仍留着 `subscribedby` | [工作原理](工作原理.md#订阅状态是怎么判断的) |
| 仍在订阅的判断以 WE 缓存为准；Steam 记录只能「保住」目录，不能把目录变成待清理 | 待清理名单完全由 `workshopcache.json` 决定，`WorkshopItemsInstalled`（内容记录）不参与订阅判断 | [工作原理](工作原理.md#订阅状态是怎么判断的) |
| 「内容在 30 分钟内被改动过就不删」看的是**目录里文件**的时间，不是目录自身的 mtime | Steam 删除内容时同样会刷新目录 mtime，只看目录会把刚被清空的残留误判成正在下载；空目录（Steam 刚建好还没开始写）才按目录自身时间保护 | [安全提示](安全提示.md)、[工作原理](工作原理.md#订阅状态是怎么判断的) |
| 单文件 exe 每次启动要先解压，约 3-8 秒 | 视机器性能而定；期间重复双击不会开出第二个窗口 | [README 的「首次运行的两个提示」](../README.md) |
| 内容完整时，「标注大小」与文件字节数基本一致 | 两者算的都是同一批内容 | [两个数字分别是什么](管理面板.md#两个数字分别是什么) |
| 文件系统按簇分配空间，「磁盘占用」通常大于「标注大小」 | 实测几个只剩着色器缓存的残留：文件合计 190.21 KB，按簇对齐约 268 KB | [两个数字分别是什么](管理面板.md#两个数字分别是什么) |
| 「磁盘占用」接近资源管理器的「占用空间」，但不逐字节相等 | 资源管理器还会算目录索引与 MFT（我们少算）；NTFS 压缩或稀疏文件会被我们高估；拿不到簇大小时这一列退回文件字节数 | [两个数字分别是什么](管理面板.md#两个数字分别是什么) |
| 「标注大小」不等于重新订阅要下载的量 | 它是上次安装时留下的记录，作者更新过内容后重新订阅会下最新版，可能更大 | [两个数字分别是什么](管理面板.md#两个数字分别是什么) |
| 移入回收站的空间要等清空回收站才真正还给系统 | — | [两个数字分别是什么](管理面板.md#两个数字分别是什么) |
| 取消订阅后启动 Steam，它会把内容删掉，往往只剩 WE 自己写的着色器缓存 | 残留形态：`shaders/blobsSM40/*.dxs`，这类目录通常只有几十 KB | [目录分类](管理面板.md#目录分类) |
| WE 自己缓存过浏览用的缩略图，可以当预览图的回退 | 路径 `<WE>\ui\thumbnails\ws_<ID>_thumb.jpg`，分辨率小、放大看会糊 | [缩略图从哪来](管理面板.md#缩略图从哪来) |
| 以 WE 的 AppID 连接 Steam 期间，Steam 会认为「Wallpaper Engine 正在运行」 | 好友状态、库页面都会体现，这是 Steamworks 的固有行为，所以工具用完即断 | [取消订阅与重新订阅](管理面板.md#取消订阅与重新订阅) |
| 「借用已安装游戏的 `steam_api64.dll` 连接 Steam」是社区通行做法，但不是 Valve 文档化的用法 | 仅供个人使用、风险自担 | [取消订阅与重新订阅](管理面板.md#取消订阅与重新订阅) |
| 任务栏与资源管理器的小图标实际是 16px | 该尺寸下认不出来就等于没有图标，所以 `make_icon.py` 每个造型都标了实测可辨认度 | [换程序图标](开发.md#换程序图标) |
| exe 未签名会让首次运行触发 SmartScreen | 没有代码签名证书时的正常现象 | [README 的「首次运行的两个提示」](../README.md) |
