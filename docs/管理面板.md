# 管理面板

```bash
python wallpaper-cleaner.py --web        # 浏览器模式
python wallpaper-cleaner.py --desktop    # 桌面窗口模式（需 pywebview）
```

浏览器模式下会自动打开 `http://127.0.0.1:8787/`，只监听本机回环地址，其他设备无法访问。

打开面板会**自动检查一遍并勾选好可清理的残留**，确认无误后直接点「清理选中」即可，不需要自己找按钮。

端口、监听地址等参数见[命令行参数](命令行.md#命令行参数)；用下载的 exe 的话把上面的 `python wallpaper-cleaner.py` 换成 `wallpaper-cleaner.exe` 即可。

## 面板能做什么

- **概览**：已订阅壁纸、磁盘文件夹、待清理、可释放空间
- **待清理列表**：列出所有不在订阅列表中的文件夹，带标题、类型与预览缩略图（点图可放大）。打开时已自动勾选「已取消订阅」的部分，想保留哪个取消勾选即可；点「磁盘占用」列头可按大小切换排序。标题与数量之间的 `?` 图标可随时打开这些规则的分点说明（内容就是下面[目录分类](#目录分类)与[两个数字分别是什么](#两个数字分别是什么)两节）
- **点标题打开目录**：两张列表的标题都可以点，用系统文件管理器（Windows 资源管理器）打开这张壁纸所在的文件夹，方便删除前先看一眼里面到底是什么；标题前面有一个文件夹图标，平时还带一条很淡的点状下划线（悬停变实线）。取不到标题的行（内容已被 Steam 清理，见[目录分类](#目录分类)）标题显示为 `打开目录`，同样可点——能不能打开目录不该由标题决定
- **删除到回收站**：默认把文件夹移入回收站而不是永久删除，误操作可以从回收站恢复
- **已订阅列表**：查看订阅中的壁纸标题、预览图、标注大小与磁盘占用，支持按 ID / 标题筛选，点「磁盘占用」列头可按大小排序；勾选后可以批量取消订阅（见下）
- **重新订阅**：在待清理列表里勾选残留的壁纸，点「重新订阅选中」，Steam 会把它们重新订阅并下载回本地；确认框会先告诉你这次大约要下载多少（见[两个数字分别是什么](#两个数字分别是什么)）
- **Steam 状态徽标**：顶栏常驻显示 Steam 是否可用（可用时还会显示你的订阅数量），不可用时点一下就能看到原因与下一步
- **高级**：位置设置（含一键自动检测，保存时会保留配置文件里的注释）、运行日志、版本与数据目录

两张表的「磁盘占用」列头都可以点，排序在 默认（不干预后端顺序：待清理本来就是大到小、已订阅是 ID 升序）→ 大到小（▼）→ 小到大（▲）之间循环。两张表各排各的，互不影响；重扫与勾选引起的重绘也不会把排序选择弄丢。

清理前会弹出确认框，逐条列出将要清理的内容与磁盘占用（合计就是这次能腾出来的空间）。

## 两个数字分别是什么

两张列表都有「标注大小」和「磁盘占用」两列，口径完全一样，但它们量的是两回事：

| 列 | 是什么 | 从哪来 |
|----|--------|--------|
| **标注大小** | 别人记下来的**内容字节数**，也就是"上次安装时多大" | Steam 的内容记录（`appworkshop_431960.acf` 里 `WorkshopItemsInstalled` 的 `size`）优先；没有时退回 WE 缓存里的标注字符串；都没有就显示「未知」 |
| **磁盘占用** | **磁盘上真实占用了多少**：文件字节数按卷的簇大小向上取整，每个子目录也算一个簇 | 扫描时自己数（`os.scandir` 遍历顺手算，不多走一遍目录） |

几个容易踩的认知点（实测数据见[已核实事实](已核实事实.md)）：

- **内容完整时，「标注大小」与文件字节数基本一致**，因为两者算的都是同一批内容；这也是为什么你会在两张表里看到两个相近的数字。
- **「磁盘占用」通常比「标注大小」大**：文件系统按簇分配空间，一个 1 KB 的文件在 4 KB 簇的卷上照样占 4 KB，小文件多的目录差距很明显（实测几个只剩着色器缓存的残留：文件合计 190.21 KB，按簇对齐约 268 KB）。这个口径接近资源管理器里的「占用空间」，但不逐字节相等——资源管理器还会算目录索引与 MFT，NTFS 压缩或稀疏文件则会被我们高估；拿不到簇大小时（非 Windows 或查询失败）这一列退回文件字节数，鼠标悬停会写明，并附上精确的文件字节合计。
- **「标注大小」不等于重新订阅要下载的量**：它是上次安装时留下的记录，作者更新过内容后重新订阅会下最新版，可能更大。所以重新订阅的确认框里写的也是「约」。
- **清理能腾出多少，看的是「磁盘占用」**：概览的「可释放空间」、清理确认框与完成提示都用这个口径（两类残留一起算）。移入回收站的空间要等清空回收站才真正还给系统。

## 取消订阅与重新订阅

这两项操作走 Steam 官方 Steamworks 接口（`ISteamUGC`），效果等同于你在 Steam 客户端里点一下，因此**需要 Steam 正在运行且已登录**。工具不接触你的账号密码，也不修改任何游戏文件。

**取消订阅**：在「已订阅壁纸」列表里勾选，点「取消订阅选中」，确认框里二选一：

| 方式 | 含义 |
|------|------|
| **仅取消订阅** | 本工具不主动删本地文件。Steam 客户端通常会在取消订阅后自行删除它们；如果留下来了，下次扫描会显示成「已取消订阅」，按残留清理即可 |
| **取消订阅并删除文件** | 取消订阅成功后由本工具再清理一次目录（默认回收站，可反选为永久删除），确保空间立刻释放。删除后本工具无法一键找回，需要到创意工坊重新订阅 |

无论哪种方式，工具都会在取消订阅后向 Steam 确认订阅确实取消了；只提交成功、迟迟没确认的会单独提示，并且**不会**去删本地的文件（那时它可能仍是订阅状态，删了会被重新下载）。

**重新订阅**：在待清理列表里勾选残留（只有纯数字 ID 的条目可以，来源不明的文件夹没有可用的 workshop ID），点「重新订阅选中」，Steam 会自动下载。文件还在本地的通常不必整包重下。

**关于 Steam 连接**：面板打开时会自动检测一次，顶栏徽标给出结论——

| 徽标 | 含义 |
|------|------|
| Steam 未检测 · 检测（灰） | 还没检测过，点一下即可检测 |
| 正在检测 Steam… | 检测进行中（在后台，不会挡住扫描） |
| Steam 可用 · N 个订阅（绿） | 已连上，N 就是你这个账号当前的订阅数量 |
| Steam 不可用 · 查看原因（黄） | 点开有具体原因与下一步：启动 Steam、重新检测，或者直接在 Steam 里手动操作 |

连不上时不会只甩一句报错：点「取消订阅选中」会弹出引导，告诉你当前是什么问题（Steam 没运行 / 没登录 / 找不到可用的 `steam_api64.dll` 等）、该怎么办，并提供一个「在 Steam 中手动操作」的跳转作为保底。

它用的是本机现成的 `steam_api64.dll`：优先用 Wallpaper Engine 自带的那份（同产品、同 AppID，且目录里已经有正确的 `steam_appid.txt`，**不写任何文件**），找不到时才退而用其它已安装游戏自带的，最后才在程序自己的数据目录下写一份 `steam_ctx/steam_appid.txt`。**永远不会往第三方游戏目录写东西**；自动查找不理想时可以在配置文件里用 `steam_dll_path` 指定。

> 需要知道的两点：以 Wallpaper Engine 的 AppID 连接 Steam 期间，Steam 会认为「Wallpaper Engine 正在运行」（好友状态、库页面），这是 Steamworks 的固有行为，因此工具**用完即断**，不留常驻连接；此外「借用已安装游戏的 dll 连接 Steam」是社区通行做法，但不是 Valve 文档化的用法，仅供个人使用、风险自担。

## 目录分类

在交叉核对（Steam 订阅记录）与新鲜度保护之后，剩余的文件夹分成两类，避免误删：

| 类型 | 判定 | 默认 |
|------|------|------|
| **已取消订阅** | 目录名是纯数字（符合 workshop ID 格式） | 打开面板时自动勾选 |
| **无法确定的文件夹** | 目录名不是纯数字，来源不明（如手动备份） | 永远不自动勾选，必须逐个手动勾选 |

两类都会显示壁纸自己的标题与类型：它们来自目录里的 `project.json`（作者随内容一起发布的名字），所以即使已经取消订阅、WE 缓存里查不到，也认得出是哪个壁纸；读不到时该列显示 `打开目录`（占位文字，仍可点开目录）。面板的待清理表格、清理确认框和命令行 `--dry-run` 预览都用这个名字。

目录里连 `project.json` 都没有时（取消订阅后启动 Steam，它会把内容删掉，往往只剩下 Wallpaper Engine 自己写的着色器缓存 `shaders/blobsSM40/*.dxs`），该行会多出一枚「内容已缺失」标记，确认框里也会注明。这类目录通常只有几十 KB，重新扫描后直接清理即可；想看清楚里面还剩什么，点标题列的「打开目录」。

## 缩略图从哪来

表格最左边一列是壁纸的预览图，首选作者随内容一起发布、已经躺在壁纸目录里的那张图（`project.json` 的 `preview` 字段，通常是 `preview.jpg` 或动图 `preview.gif`；字段缺失或不可信时按 `preview.jpg` → `preview.png` → `preview.jpeg` → `preview.gif` 依次找）。面板只把这张图的字节发出去，解码、缩放、动图播放都由浏览器完成，所以：

- 不联网、不问 Steam 要图，也不新增任何依赖（仍是纯标准库）
- 动图在列表里是**真的会动**的，点一下还能放大看原图
- 目录里那张原图也没有时（内容已被 Steam 清理），回退到 Wallpaper Engine 自己缓存的浏览缩略图 `<WE>\ui\thumbnails\ws_<ID>_thumb.jpg`——同样是本地文件，只是分辨率小、放大看会糊，鼠标悬停在图上会说明它的来源
- 两处都没有时显示一个虚线占位框，不会去猜、也不会去解码视频

接口 `GET /api/thumb?wid=<ID>` 只认最近一次扫描结果里的目录：ID 与文件名都来自扫描本身（回退的缩略图文件名也是由 ID 精确拼出来的，不扫描目录），不接受请求里带来的路径，读之前还会再校验一次文件确实在壁纸目录（或 WE 的缩略图目录）内、是图片、且不超过 8 MB。
